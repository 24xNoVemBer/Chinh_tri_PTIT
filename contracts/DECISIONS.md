# Contract decisions

| ID    | Decision                                                                                                                                                                    | Rationale                                                             |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| D-001 | Browser calls PTIT Backend only; it never calls RAG/model directly.                                                                                                         | Keeps auth, class scope, audit and provider credentials server-side.  |
| D-002 | `requestId` is generated by the backend and is stable across retries.                                                                                                       | Enables tracing and idempotent reconciliation.                        |
| D-003 | `idempotencyKey` is unique per student and request intent. Same key + same payload replays the original result; same key + different payload is `409 IDEMPOTENCY_CONFLICT`. | Prevents duplicate jobs and duplicate answers.                        |
| D-004 | RAG receives an allow-list of approved `materialVersionId` values.                                                                                                          | A citation outside the allow-list is never publishable.               |
| D-005 | A successful answer is visible immediately as `provisional`; publication/review is independent state.                                                                       | Supports the product requirement while retaining governance.          |
| D-006 | Every citation carries immutable material/version/chunk/checksum metadata.                                                                                                  | Allows deterministic citation validation and audit.                   |
| D-007 | Terminal answer delivery is JSON or SSE behind the backend.                                                                                                                 | SSE gives responsive UI without exposing the provider.                |
| D-008 | Times are integer milliseconds and timestamps are RFC 3339 UTC.                                                                                                             | Avoids locale/precision ambiguity between teams.                      |
| D-009 | RAG is not the source of authorization.                                                                                                                                     | Backend owns Entra identity, role, enrollment and course scope.       |
| D-010 | Phase 0 ships schemas, mocks and contract tests only; production queue/DB changes are deferred.                                                                             | Lets both teams integrate safely without disturbing the current demo. |
